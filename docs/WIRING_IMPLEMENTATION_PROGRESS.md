갱신일: 2026-10-04

기준: [전체 계획](WIRING_Z_LAYER_COMPONENT_PLAN.md),

## 이번 구현 범위

전체 계획을 완료한 상태는 아니다. A의 배선 기반, B의 기존 부품
Z 판정, C의 높이 편집/저장 기반, D의 공압 3종, E의 서보/DC 축과
F의 창고·광화이버·HMI를 연결했다.

- 배선 도구 하나로 통합. 시작 포트에서 Wire 종류 결정.
- 전기/공압/광 enum을 네트워크 분류·미리보기·선/태그 렌더·저장에 사용.
- 다른 타입 연결, 광 TX/RX 역할 오류, 중복 연결을 거부.
  잘못된 대상 클릭은 시작 핀과 중간 점을 유지.
- 완료 시 두 끝을 실제 부품/포트 ID로 조회. 공유 임시 포트 버퍼 때문에
  시작/대상 검증이 같은 포트를 읽을 수 있던 경로 제거.
- 광 포트는 연결 수 1개로 제한. 기존 전기 분기와 공압 분배 유지.
- 기존 `is_electric` 저장 파일을 읽고 새 파일에는 `wire_kind` 저장.
  저장 타입과 실제 포트가 불일치하면 연결을 유효 네트워크에 넣지 않음.
- 물리 Z 설정/상태 추가. 기본 고정 높이 1, 가공 실린더 기본 범위 1~2.
  기존 스트로크 15~30을 설정 범위에 매핑.
- Box2D 공간 검색에서 높이가 맞는 후보만 수집/선택. 검색 중 최대 index
  선택보다 Z 필터가 먼저 적용됨. 센서 광선·이송·실린더·가공·박스에 적용.
- XY 공간 격자 폴백 및 외부 센서 폴백에도 공통 높이 판정 연결.
  높이를 반올림하지 않으며 그리기 순서와 독립.
- 부품 목록 옆 화살표와 컨텍스트 메뉴에서 Z 편집 창 접근.
  고정 높이/가공 범위 및 현재 높이 확인. 실제 물리 일시정지 후
  검증된 편집 명령으로 적용하고 Undo/Redo 지원.
- Z 초기 설정을 저장/복원. 무효 범위는 기존 장면 변경 전에 거부.
- 신규 UI의 한국어/영어/일본어 문자열 추가, 이전 도구 안내 제거.
- Windows GUI 실행 파일에서 `main`을 사용하는 MSVC 진입점 설정 보완.

새 포트 검증은 광 TX/RX, VAC, AC 전력·서보 상·엔코더와 고속 펄스
역할을 검사한다. 모델별 전력/통신 프로필은 후속 범위다.

## 아직 구현하지 않은 항목

- 프로젝트 레이어 목록/추가/표시 필터와 통합 공정 시나리오.
- 가상 낙하·진공 누설·광 수광량의 정밀 물리 모델.
  현재 고정 부품/가공 실린더/스토퍼/서보 축 범위, 창고 슬롯과 소유 해제를 지원한다.
- 폴백 경로를 강제로 실행하는 별도 회귀 테스트와 UI 시각 검증.

## 검증 기록

Release의 `PLCSimulator`, `application_runtime_tests`, `ladder_rewrite_tests`
전체 재빌드 성공. `ladder_runtime`, `ladder_physical`, `application_runtime`
3개 모두 통과(최종 CTest 실행 4.52초). `git diff --check` 통과.

실행 파일: `cmake-build-p1-msvc/bin/PLCSimulator.exe`.
이번 검증에 사용한 해당 로컬 CMake 구성은 Release로 전환했다.

추가 회귀는 실제 앱의 연결/저장/Undo 명령과 공유 Box2D 함수를 호출한다.
자동 타입, 잘못된 대상에서 경로 유지, 역방향 중복, 광 역할,
구버전/신버전 저장, Z 편집 정지 정책/Undo/Redo, 무효 높이 로드 거부,
다른 높이 이송/센서 분리, Z만 변경한 경우, 최대 index 상자 선택을 포함한다.

빌드 환경: 기존 Debug 구성에서 MSVC C1902 디버그 정보 관리자 오류가
발생해 이번 검증은 Release로 수행한다. 기존 `serial_execution.cpp`와
`modbus_execution.cpp`의 변환 경고 C4244/C4267은 검증 명령의 `CL`
환경에서만 제외한다. 프로젝트의 `/WX` 설정이나 해당 프로그래밍 소스는
변경하지 않는다. 따라서 두 경고를 포함한 엄격한 빌드가 통과했다는 의미는 아니다.

공통 구조체 변경 후 증분 빌드에서 메모리 오류가 발생했다. 로컬 CMake의
한글 MSVC include 의존성 접두사가 깨져 헤더 변경을 추적하지 못한 것을
확인했고, 생성된 컴파일러 설정의 접두사를 복구한 뒤 전체 재빌드했다.
동일 테스트가 이후 모두 통과했다. 해당 보정은 로컬 빌드 디렉터리에만 적용했다.

다음 구현 연결 지점은 G의 통합 공정·성능/회귀다.
기존 가공 부품을 중복 생성하지 않고 축 상태와 흡착 소유 모델을 재사용한다.


## D 묶음 추가 구현 (2026-10-04)

- 센서 내장 복동/흡착/스토퍼를 별도 타입으로 등록하고 자동화 부품 목록,
  실제 배선 포트, 저장/로드에 연결했다. 기존 실린더 목록은 유지한다.
- 기존 실린더 물리 어댑터를 3종 모두 공유한다. 고정 enum 순서 배열이던
  behavior/physics adapter를 행동이 있는 타입 중심의 sparse switch로 정리했다.
- 내장 FWD/REV 또는 DOWN/UP 출력은 현재 스트로크에서 계산한다.
  실제 전기 해석 단계에서 이번 네트워크의 24V/0V를 확인한 뒤 NPN/PNP
  출력을 부여하므로 전원 단절을 이전 프레임 상태로 계속 출력하지 않는다.
  실제 PLC X 입력, 입력 모드 자동 변환, 저장/로드까지 검증했다.
- 상단 소형 센서 단자대, 기존 복동 몸체, 폭을 통일한 아래 방향 흡착 헤드를
  네이티브 도형으로 표시한다. VAC 앵커는 실제 헤드 이동을 추종한다.
- 진공원이 없던 기존 구조를 위해 공압식 진공발생기를 보조 목록에 추가했다.
  양압 공급과 진공 출력을 분리해 해석하고, 양압/배기 오염은 해당 진공 회로만
  무효화한다. 양압 챔버↔VAC 연결은 배선 도구와 로드에서 거부한다.
- 안정적인 공작물 ID 기반 흡착 소유, 후보 ID 선택, 상대 XY/Z 추종,
  진공 상실/수동 드래그/소유 부품 삭제 시 현재 위치 해제를 추가했다.
  소유 중에는 컨베이어/자유 로드/가공/박스 스냅이 공작물을 움직이지 않는다.
  흡착 헤드를 기존 자유 로드 스냅 대상으로 처리하지 않아 방출 후 다시
  붙거나 위치가 점프하지 않는다.
- 스토퍼 스트로크는 수납 최대 Z→하강 최소 Z에 대응한다. 하부 판 로컬
  영역의 경로 충돌을 Box2D와 격자 폴백 양쪽에서 공통 사용한다.
  빠른 공작물의 관통과 판 내부 이송을 막고, 상승 시 통과시킨다.
  컨베이어 모터 전원을 자동으로 바꾸지 않는다.
- 정면 확인 창은 상태를 읽기만 하며 실제 XY/배선 앵커를 바꾸지 않는다.
  정면에서 축은 수납 시 그리지 않고 하강 시만 노출한다.
- 신규 부품을 포함한 장면은 공유 기본 물리 경로로 실행한다. 미지원 부품을
  고급 엔진이 덮어쓰지 않도록 명시적으로 분기했다.
- 일시정지 높이 편집은 관련 흡착 소유를 해제한다. 점유 창고 이동 정책과
  진공 누설/중력, 사용자 스트로크 설정, NO/NC 전환은 이번 단계에서 미구현이다.

검증은 기존 3개 CTest에 실제 배선 NPN/PNP 출력과 전원 손실, 새 타입 저장,
이동 VAC 포트/역할 검사, 3종 공통 압력 구동, 스토퍼 정지/상승/빠른 경로,
흡착 Z/소유/추종/해제/후속 이송/후보 순서/독립 회로 오염을 추가했다.
추가 부품의 숫자 핀 ID와 모델 수치는 [부품 명세 15절](WIRING_NEW_COMPONENT_SPEC.md#15-d-묶음의-실제-구현값-2026-10-04)에 기록한다.

UI 창을 직접 조작한 시각 검증은 아직 하지 않았다. 네이티브 렌더 코드와
상태/배선/물리 경로의 자동 테스트 통과를 화면 검증으로 대신 표기하지 않는다.

D 묶음 최종 검증: 세 실행 파일 Release 빌드 성공, CTest 3/3 통과
(4.92초), `git diff --check` 통과. 기존 경고 제외/빌드 환경 제한은 위와 같다.


## E 묶음 추가 구현 (2026-10-04)

- DC 모터/서보 모터/서보앰프/서보 리프트/흡착 일체형과 보조 3상 AC 공급을
  별도 목록 항목으로 등록했다. 형상은 기존 회색 몸체와 원형 핀을 유지한다.
  모터는 정면, 일체형 기본은 실제 상부 단면이며 로드는 오른쪽으로 이동한다.
  서보 리프트/일체형은 정면에서 높이 이동을 확인할 수 있다.
- 타입/설정 검증과 도형 요소를 공유해 기존 실린더 계산과 소유 모델을
  일체형에서도 사용한다. 서보와 공압/진공의 실패는 각 축에 별도로 적용한다.
- PLC 고속출력에 단조 누적 정/역 펄스와 리셋 epoch를 추가했다.
  명령별 카운터 초기화 때문에 반복 PLSY의 물리 펄스를 잃지 않는다.
  240Hz ON 샘플 대신 실제 생성 수를 소비하며 방향 연결도 검증한다.
- 실제 상/ENC/PE/전원/SON/PULSE/P-COM을 모두 확인하고 동작한다.
  AC와 서보 상, ENC는 기존 DC 해석에 합치지 않는다.
  잘못된 역할, 단일 연결 대상의 중복을 배선 완료/호버/로드에서 검사한다.
- 누적 지령을 회전당 펄스로 환산하고 속도/가속도 한계로 실제 축이 추종한다.
  리프트는 리드/스트로크에서 연속 Z를 계산하며 범위 초과를 알람으로 처리한다.
  SON 해제/연결 단절 중 펄스는 복구 때 재생하지 않고 위치를 유지한다.
- READY/INP/ALARM은 실제 상태를 전기 네트워크에 제공한다.
  상태가 전환되면 같은 물리 스텝의 PLC 입력에 반영한다.
  RESET은 원인이 제거된 경우에만 알람을 지운다.
- 일시정지 중 축 설정을 변경하고 저장/로드/Undo/Redo를 사용한다.
  제로 리드 등 무효 설정은 기존 장면을 변경하기 전에 거부한다.
  높이/축 설정 변경은 연결 앰프 커서와 해당 흡착 소유를 정리한다.
- DC 모터는 전압 차이에 따른 속도/방향과 감속을 지원한다.
  배치만으로 주변 기계에 연결되는 동작을 추가하지 않았다.

검증: 실제 DDRVI 20kHz 프로그램 → 배선 → 서보앰프 → 일체형 리프트 →
연속 Z → READY/INP → PLC X 입력의 앱 경로가 통과했다. 공유 물리 테스트는
1000개 sub-tick 펄스, 속도 추종, 두 축 흡착, ENC 단절/RESET, SON 무효 펄스,
리셋 커서, 기계 한계, DC 감속을 검증했다. 기존 펄스 명령 회귀에는
명령 사이에 유지되는 하드웨어 누적 수와 epoch 초기화 검사를 추가했다.

실물 파형/브레이크/원점 복귀/관성 부하, 다중 PLC 별도 실행, 내부 접점을
통과하는 고속 펄스, 모델별 단상/차동/CW-CCW와 HMI 매핑은 후속 범위다.
기존 물리 고급 엔진의 미지원 모델은 공유 기본 경로로 실행한다.


### E 화면 확인과 재현

실제 ComponentDefinition 렌더 함수와 앱의 ImGui/OpenGL 렌더 경로로
[네이티브 부품 미리보기](design_assets/native_components_e_preview.png)를 생성했다.
모터 정면의 원형 몸체, 앰프의 몸체 부착 단자, AC/리프트 단자 식별,
일체형의 오른쪽 로드와 정면의 아래 방향 흡착 헤드·센서 단자를 확인했다.
평면/정면은 명시적인 렌더 분기로 구분해 캐리지 높이에 따라 투영이 바뀌지 않는다.

재현은 `application_runtime_tests.exe --render-parts`로 가능하다.
실제 렌더 결과를 `tmp/native-components-preview.ppm`으로 저장한다.
이 확인은 네이티브 부품 도형 검증이며 메뉴·설정 창을 사람이 직접 조작한
전체 UI 검증은 아직 수행하지 않았다.

E 묶음 최종 검증: `PLCSimulator`, `application_runtime_tests`,
`ladder_rewrite_tests` Release 빌드 성공. CTest 3/3 통과(4.84초),
네이티브 렌더 이미지 생성 성공, `git diff --check` 통과.
기존 변환 경고의 명령 한정 제외와 Debug 빌드 제한은 위 검증 기록과 같다.


서보앰프 크기 보정: 몸체 높이를 PLC와 같은 180으로 맞추고 기존 형상,
글자·단자·배선 앵커를 동일 비율(180/354)로 축소했다. 포트 ID/역할은 유지한다.
네이티브 미리보기에 PLC 높이 비교를 추가했다. 앱 Release 재빌드 및

## F 묶음 추가 구현 (2026-10-04)
