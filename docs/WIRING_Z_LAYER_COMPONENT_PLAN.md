# 실배선 신규 부품 및 물리 Z-레이어 구현 계획

작성일: 2026-10-04  
상태: 코드 조사와 사용자 요구사항에 기반한 구현 계획. 기능 구현은 아직 하지 않음.

관련 상세 명세: [신규 부품 물리 동작·핀아웃](WIRING_NEW_COMPONENT_SPEC.md).
변경 파일과 기능 경계: [실배선 확장 변경 범위](WIRING_IMPLEMENTATION_SCOPE.md).
부품별 구동 조건, 논리 포트 ID/역할, 전원·압력 상실 처리와 검증 기준은
해당 명세를 함께 적용한다. 제조사 물리 핀 번호와 시뮬레이터 논리 포트는 구분한다.

## 1. 목적과 확정 요구사항

실배선 모드는 2D XY 캔버스를 유지한다. 실물에서 위아래로 움직이는
가공 헤드, 서보 리프트, 흡착 공작물, 다단 창고의 높이는 별도의
**물리 Z-레이어**로 표현한다. 평면 디자인을 추가한 이유는 실제 배치와
운전을 위해서이며, 단순한 이미지 회전이나 장식용 미리보기가 아니다.

- 캔버스의 앞/뒤 그리기 순서와 물리 Z-레이어는 독립된 시스템이다.
- XY가 같아도 접촉 높이가 다른 부품과 공작물은 물리적으로 반응하지 않는다.
- 가공 실린더의 기본 이동 범위는 2개 레이어다. 상승 높이 2,
  하강 높이 1을 기본 예제로 사용한다.
- 서보 리프트의 기본 이동 범위는 3개 레이어다. 상승/하강 위치에 따라
  현재 높이가 변하며, 이동 범위 내에서 자유롭게 이동한다.
- 6칸 창고는 3개 높이에 각 2칸씩 저장한다.
- 각 부품의 높이와 이동 범위는 편집할 수 있어야 한다. 특정 부품 타입을
  전역 레이어 1/2/3에 영구적으로 고정하지 않는다.
- 더블클릭 메뉴에서 높이 설정을 편집한다. 부품 리스트 옆 화살표로
  별도의 Z-레이어 편집 창을 연다.
- 공압/전기 도구를 **배선 도구 하나로 통합**한다. 시작 핀의 타입으로
  전기/공압/광 연결 종류를 자동 결정하며 사용자가 종류를 선택하지 않는다.
- 앞면 디자인은 더블클릭 메뉴의 `수평으로 보기`에서 확인할 수 있게 한다.
  이는 물리적인 회전 명령이 아니라 별도 투영 표시다.
- 창고는 적재 시 또는 호버 시 작은 앞면 오버레이로 적재 상태를 보여준다.
- 비금속을 3번, 2번 창고에 순차 적재하고 금속을 배출박스로 보내는
  공정을 표현할 수 있어야 한다. 분류 순서 자체는 PLC 프로그램이 결정한다.

대화에서 언급한 `가공 리프트`는 기존에 설계한 **서보 리프트 및
흡착 실린더 일체형의 수직 축**으로 해석한다. 별도의 가공 리프트 타입이
필요하다는 의미였다면 타입 추가 전에 명칭만 확인한다. 본 계획에서는
가공 실린더와 서보 리프트를 구분한다.

축 상태 처리만 필요한 만큼 재사용한다. 일체형은 내부에서 리프트와
실린더 처리를 재사용하며 숨겨진 별도 배치 부품을 생성하지 않는다.

## 4. 물리 높이 모델

### 4.1 세 개념을 분리한다

1. **그리기 순서**: 기존 `z_order`. 어떤 그림이 앞에 그려지는지만 결정.
2. **허용 높이 범위**: 액추에이터가 도달할 수 있는 최소/최대 높이.
3. **현재 작용 높이**: 지금 공작물에 닿을 수 있는 헤드·판·감지면의 높이.

예를 들어 리프트가 1~3 범위를 가진다고 해서 세 레이어의 공작물에
동시에 닿는 것은 아니다. 현재 헤드가 2에 있으면 높이 2에서만
작용한다. 창고는 반대로 3개 높이에 실제 저장면을 각각 가진다.

고정 몸체, 이동 헤드, 저장면은 하나의 부품 안에서도 다른 물리 영역이다.
단일 부품의 전체 그림 AABB를 모든 높이의 장애물로 쓰지 않는다.
첫 구현에서는 필요한 접촉면만 모델링하며, 장비 전체의 3D 충돌을
흉내 내는 범용 강체 시스템까지 확장하지 않는다.

### 4.2 설정과 런타임 상태

`PlacedComponent`에 다음 정보를 타입이 있는 값으로 둔다. 아래 이름은
설계 예시이며 최종 구조체 배치는 구현 시 결정한다.

| 정보 | 성격 | 의미 |
| --- | --- | --- |
| `ZLayerConfig` | 편집/저장 | `min_layer`, `max_layer`, `initial_height`, 허용 오차 |
| `ZMotionState` | 런타임 | 현재 높이, 목표 높이, 속도, 도착/이동 여부 |
| `ComponentViewMode` | 편집/저장 | 기본 평면 또는 보조 정면 표시 |
| `WorkpiecePlacementState` | 런타임 | 자유 상태 / 흡착 중 / 창고 적재 / 배출박스 저장 |
| 창고 슬롯 설정 | 편집/저장 | 안정적인 슬롯 ID, 높이, XY 저장 영역 |
| 창고 슬롯 점유 | 런타임 | 비어 있음 또는 공작물 instance ID |

공작물 ID나 슬롯 ID를 `std::map<std::string, float>`에 넣지 않는다.
기존 `internalStates`의 센서/모터 키는 필요한 곳에서 유지하되 높이·소유
관계는 단일한 타입 모델을 기준으로 한다. 설정값과 파생 런타임 값을
두 군데서 수정할 수 있는 구조를 피한다.

### 4.3 연속 이동과 레이어 접촉

- 편집 창의 레이어 번호는 1부터 시작한다. 전체 레이어 수는 3에 고정하지
  않고 프로젝트에서 확장할 수 있다.
- 이동 높이는 실수로 관리한다. 예: 1 → 1.35 → 2 → 2.7 → 3.
- 정수 레이어는 정지/서비스 높이다. 이동 중 현재 높이를 무조건 반올림해
  인접 레이어 공작물에 접촉시키지 않는다.
- XY 접촉에 더해 접촉면 높이가 공작물 높이와 허용 오차 이내인지 판정한다.
  허용 오차는 수치 안정성용이며 레이어 간격보다 충분히 작아야 한다.
- 창고 적재는 해당 서비스 높이에 도착하고 속도가 허용값 이내일 때만
  가능하다. 통과 중에는 슬롯에 순간 적재하지 않는다.
- 부품 타입별 기본 범위는 프리셋일 뿐이다. `[1,2]`를 `[4,5]`로
  바꾸면 같은 가공 실린더가 하강 4 / 상승 5에서 동작해야 한다.
- 이동 범위가 확장되더라도 현재 접촉 높이와 창고 서비스 높이를 따로
  관리한다. 6칸 창고가 범위 확장 때문에 8칸, 10칸으로 늘어나지는 않는다.

일반 고정 부품의 기본값은 `min_layer == max_layer == initial_height == 1`.
자동 구동 축의 현재 높이는 축 위치로부터 계산한다. 실행 중 편집 창에서
현재 높이를 임의로 덮어써서 공작물을 순간이동시키지 않는다.

## 5. 부품별 Z 동작

Z 매핑은 아래 공통 규칙을 따르며, 구동/센서 조건은
[물리 동작·핀아웃 명세](WIRING_NEW_COMPONENT_SPEC.md)의 해당 부품 절을 따른다.

| 부품/작용면 | 기본 예제 | 동작 원칙 |
| --- | --- | --- |
| 공작물 | 높이 1 | 자유 상태에서는 자기 높이 유지. 소유자가 있으면 소유자의 접촉 높이 추종 |
| 컨베이어 | 운반면 1 | 같은 높이의 자유 공작물만 이송 |
| 일반/센서 내장 실린더 | 접촉 높이 1 | 기본 XY 스트로크는 유지. 센서 내장 여부로 별도 이동식을 복제하지 않음 |
| 가공 실린더 | 상승 2, 하강 1 | 기존 스트로크 상태를 설정 범위의 Z로 매핑. 높이 일치 + XY 겹침 + 모터 동작 시 가공 |
| 서보 리프트/일체형 | 1~3 | 서보 축 위치가 Z를 변경. 일체형 실린더 전후진은 XY를 변경 |
| 스토퍼 | 상승 2, 차단 1 제안 | 판 높이가 컨베이어 공작물 높이에 닿았을 때 차단. 범위는 편집 가능 |
| 6칸 창고 | 저장면 1, 2, 3 | 저장면별 2칸. 창고 범위 전체가 한 개의 흡입/저장 영역이 아님 |
| 배출/저장박스 | 받는 높이 1 | 높이가 맞는 자유/방출 공작물만 수납 |
| 외부 감지 센서 | 감지 높이 1 | 다른 높이의 공작물과 축 끝단을 감지하지 않음 |
| 내장 전후진 센서 | 내부 축 상태 | 주변 부품의 Z를 감지하는 것이 아니라 자기 스트로크의 끝단을 검출 |
| 전원·PLC·앰프·터치패널 | 편집상 높이 가능 | 전선으로 연결된 신호는 Z 차이 때문에 차단하지 않음 |

기존 가공 실린더의 `position`은 상승 30 / 하강 15로 사용 중이다.
이를 즉시 다른 의미의 높이 값으로 바꾸지 않고, 해당 스트로크를
정규화해서 사용자가 설정한 Z 범위로 매핑한다. 렌더·센서 끝단·물리에서
중복된 끝단 상수는 이때 공통 설정으로 정리한다.

가공 헤드가 상승한 상태에서 XY 겹침만으로 공작물을 끌어당기거나
고정하는 현재 경로도 함께 교정한다. 가공 완료는 Z 접촉과 모터 조건을
모두 만족해야 한다. 같은 높이인 것만으로 자동 가공되는 것은 아니다.

## 6. 접촉 판정과 물리 엔진 연결

공통 함수 예시: `CanInteractAtHeight`, `ResolveContactHeight`,
`GetInteractionSurfaces`. 가공·흡착·센서·저장·이송이 같은 높이 규칙을 쓴다.

처리 순서는 다음과 같다.

1. 전기·공압·서보 지령으로 축 상태를 갱신한다.
2. 축 위치에서 현재 Z와 작용면을 계산한다.
3. 흡착 중 공작물의 XY·Z를 소유자에 맞춰 갱신한다.
4. XY 공간 질의로 후보를 구하고 Z 조건을 적용한다.
5. 스토퍼 차단, 이송, 센서, 가공, 흡착/방출/적재 효과를 적용한다.
6. 최종 상태를 렌더와 PLC 입력에서 일관되게 읽도록 갱신한다.

실제 PLC 입력 샘플링 시점은 기존 물리/PLC 스캔 순서를 유지하고,
동일 물리 스텝의 갱신 결과를 사용하는지 검증한다.

### 6.1 Box2D 및 폴백

- 현재 Box2D는 주로 공간 검색을 담당한다. 그 뒤 코드에서 직접 수행하는
  이송·가공·스냅·센서·상자 저장에도 Z 필터를 넣는다.
- `QueryOverlaps`, `BeamOverlaps`, `QueryMaxIndex` 등에 질의자의
  높이/작용면을 전달한다. 특히 최대 index 후보 선택 **전에** Z를 검사한다.
  다른 높이의 상자를 먼저 골라 같은 높이의 상자를 놓치면 안 된다.
- 도형 타입 category bit를 높이 번호로 대체하지 않는다. 높이별 bit만
  쓰면 레이어 수와 연속 높이 표현에 제한이 생긴다.
- 공간 격자 폴백과 고급 물리 경로에서도 같은 공통 판정을 호출한다.
  지원하지 않는 경로는 명시적으로 공유 구현에 위임한다. XY만 보는
  경로를 남긴 채 지원 완료로 처리하지 않는다.
- Z를 바꿨을 때 XY가 그대로여도 잠든 공작물과 캐시를 갱신한다.
  도형 캐시는 ID/역할을 유지하되 질의 높이는 최신 상태를 읽는다.
- Z 변경 시 `proc_ready`, `snap_lock`, 이전 센서 감지처럼 XY에만
  의존한 잠금/접촉 상태가 남지 않게 한다.
- 서로 다른 Z의 공작물끼리도 차단·스냅·흡착 대상 선택에서 분리한다.
- 렌더 숨김, 화면 바깥, 낮은 확대율이 물리 동작을 중지시키지 않도록
  기존 LOD/수면 조건에 Z 이동과 소유 관계를 반영한다.

전체 접촉 필터는 효과 적용 직전에도 확인한다. 한 스텝 안에서
흡착·방출 등으로 상태가 변해 이전 후보가 무효가 될 수 있기 때문이다.

## 7. 흡착·운반·방출

공작물은 한 순간에 한 소유자만 가진다. 리프트에 흡착된 공작물을
컨베이어나 다른 실린더가 동시에 이동시켜서는 안 된다.

상태 전이:

`자유 → 흡착 중 → 창고 적재 / 배출박스 저장 / 자유`

- 흡착: 진공 구동 정상, 실제 XY 접촉, Z 높이 일치, 자유 상태가 모두 필요.
- 운반: 공작물의 상대 XY 위치를 보존하고 Z는 헤드 높이를 추종.
- 방출: 소유자 해제와 적재 대상 선택을 한 단계로 처리한다.
- 유효 창고 슬롯에 도착했으면 공작물 ID를 슬롯에 옮긴다.
- 유효 수납면이 없으면 현재 XY·Z의 자유 공작물로 남긴다. 자동으로
  레이어 1로 순간이동시키지 않는다. 낙하 물리는 첫 구현 범위에 넣지 않는다.
- 점유된 슬롯에는 새 공작물을 덮어쓰지 않는다. 실패 시 기존 공작물은
  보존하고 UI 상태에 적재 실패를 표시한다.
- 삭제·초기화·Undo 시 소유자/슬롯 참조를 ID로 재검증한다. 벡터 index나
  포인터를 장기 참조로 저장하지 않는다.

한 tick의 높이 변화가 크더라도 목표 높이에 도착하지 않고 슬롯 적재를
건너뛰거나 수행하지 않게 한다. 목표 위치 clamp와 도착 조건을 검증한다.

리프트 높이 편집 시 일체형 흡착부와 운반 공작물에 같은 기준 변경을
적용한다. 점유 중인 창고의 서비스 높이를 바꾸거나 범위를 줄일 때는
공작물을 범위 밖에 남기는 부분 적용을 금지한다. 정지 상태에서 관련
초기 배치를 함께 옮기거나 편집을 거부하는 원자적 명령으로 처리한다.

## 8. 6칸 창고

### 8.1 논리 슬롯과 번호

몸체 그림에는 번호를 넣지 않지만, 슬롯 선택과 PLC 테스트에서는
안정적인 논리 번호가 필요하다. 기본 번호는 다음과 같이 제안한다.

| 높이 | 왼쪽 | 오른쪽 |
| --- | --- | --- |
| 상단, 기본 Z=3 | 5번 | 6번 |
| 중단, 기본 Z=2 | 3번 | 4번 |
| 하단, 기본 Z=1 | 1번 | 2번 |

따라서 사용자 예제의 **3번 → 2번 적재**는 중단 왼쪽 → 하단 오른쪽
순서가 된다. 슬롯 번호와 Z 번호를 혼동하지 않는다. 표시 순서를 바꿔도
기존 슬롯 ID와 PLC 목표의 의미는 유지한다.

창고의 기준 범위를 옮기면 세 서비스 높이도 함께 이동한다. 범위를
늘리는 경우 세 높이를 설정 안에서 명시적으로 지정한다. 슬롯의 XY
영역과 Z 서비스 높이는 함께 맞아야 하고, 총 점유는 항상 최대 6개다.

### 8.2 적재 조건과 데이터

- 슬롯은 `slot_id`, `service_height`, `local_xy_area`, `occupant_id`를 가진다.
- 감지 후보는 XY에 겹친 슬롯 중 서비스 높이가 맞는 슬롯이다.
- 같은 XY에 있는 상단/중단/하단 중 하나만 선택한다.
- 리프트 목표가 바뀌거나 점유 상태가 바뀌면 같은 높이의 다른 슬롯을
  프로그램 명령 없이 임의 선택하지 않는다.
- 적재 공작물은 자기 높이를 유지한다. 다른 단의 공작물과 겹쳐도
  컨베이어에 끌려가거나 다른 슬롯을 막지 않는다.
- 기존 박스의 단일 `is_stuck_box`로 다단 창고를 구현하지 않는다.
- 초기 적재 설정과 현재 런타임 적재 상태를 구분한다.

### 8.3 표시

평면은 두 열의 저장 영역만 보이며, 높이가 다른 단은 XY에 겹친다.
정면 오버레이에서는 실제 점유된 칸에 공작물의 색/재질/가공 상태를 그린다.
원형 표시는 공작물이 있을 때만 나타난다.

- 마우스 호버 시 작은 정면 오버레이 표시.
- 적재 성공 또는 상태 변경 시 짧게 자동 표시하고, 변경 없으면 반복 표시하지 않음.
- 오버레이는 클릭 판정·물리 높이·원래 배치 크기를 바꾸지 않음.
- 실행 중 가려진 단을 확인하기 위해 선택 Z와 점유 요약을 표시.
- 빈 슬롯을 현재 Z의 공작물로 착각할 수 있는 장식 원은 사용하지 않음.

## 9. 화면과 조작

### 9.1 더블클릭 메뉴

기존 컨텍스트 메뉴에 `Z-레이어`와 `수평으로 보기`를 추가한다.

- 고정 부품: 설치 높이 편집.
- 이동 축: 최소/최대/초기 높이 편집, 현재 높이 읽기 전용 표시.
- 창고: 세 서비스 높이와 슬롯 점유 확인.
- 입력값 검증: 유한수, 최소≤최대, 초기 높이가 범위 안, 서비스 높이
  순서와 중복, 프로젝트 레이어 범위.
- 기존 버튼/비상정지의 더블클릭 동작을 유지하고 메뉴를 여는 별도
  경로를 제공한다. 현재 우클릭 컨텍스트 경로도 유지한다.

`수평으로 보기`의 내부 의미는 **정면 투영 확인**이다. 기존 `회전 90도`
또는 `좌우 반전`으로 처리하지 않는다. 기본 실배선 배치는 평면을 사용한다.
첫 구현에서는 메뉴를 통해 정면 미리보기를 열도록 하고, 캔버스 투영
전환까지 제공하면 포트/배선/물리 앵커를 바꾸지 않는 보조 표시로 한정한다.

### 9.2 Z-레이어 편집 창

부품 리스트 창 옆에 화살표 버튼을 추가한다. 버튼은 Z 편집 창의
열기/닫기만 담당하며 기존 리스트 보기 전환 버튼과 겹치지 않게 배치한다.

창에는 다음 내용을 표시한다.

- 프로젝트 레이어 목록과 레이어 추가.
- 부품별 설치 높이 또는 이동 범위, 현재 높이, 표시 모드.
- 부품 선택 시 캔버스 선택과 연동.
- 선택 레이어의 공작물·작용면 강조. 다른 레이어는 흐리게 볼 수 있음.
- 범위를 가진 부품은 여러 레이어에 범위 표시를 하되 현재 작용 높이는
  별도 표시. 창고는 저장면과 각 슬롯 점유를 표시.
- 숨긴 레이어의 부품을 선택하려면 패널에서 선택하거나 레이어 필터를 변경.
  그리기 순서가 높은 다른 높이 부품이 항상 클릭을 가로채지 않게 함.

레이어 숨김/강조는 표시 필터다. 전기·공압·광 연결 또는 물리 실행을
일시 중지시키는 기능으로 사용하지 않는다. 캔버스의 앞뒤 순서 명령도
높이를 변경하지 않는다.

### 9.3 실행 중 편집 정책 제안

실행 중에는 현재 높이·점유 상태를 보여주고, 범위/설치 높이/초기 적재의
변경은 정지 상태에서 적용한다. 실시간 변경을 나중에 허용할 경우에도
UI 직접 쓰기가 아니라 검증된 명령을 스텝 경계에서 적용해야 한다.
PLC STOP은 현재 코드에서 물리 정지와 같지 않으므로, 편집 가능 여부는
PLC RUN 표시만으로 판단하지 않고 실제 시뮬레이션 편집 상태로 정의한다.

## 10. 표시 형상과 물리 형상의 분리

- `RenderTop`, `RenderFront`, `RenderOverlay`가 같은 논리 상태를 읽는다.
- 렌더 함수를 재사용하되 정면과 평면을 이미지 회전으로 만들지 않는다.
- 물리 영역/포트 앵커는 렌더 함수의 도형이나 화면 좌표에서 역산하지 않는다.
- 부품 크기, 선택 영역, 포트 위치는 기본 평면 배치 기준으로 안정적으로 유지.
- 정면 오버레이를 열어도 전선 끝점, 호스, 광 연결선이 이동하지 않는다.
- 실제 캔버스 회전/반전은 XY 로컬 물리 좌표와 포트 앵커에 공통 적용한다.
  Z 축 방향은 회전/반전으로 뒤집히지 않는다.
- 일체형의 헤드 XY는 실린더 스트로크로, Z는 리프트 축 위치로 계산한다.
  이 두 자유도를 하나의 `position` 값으로 합치지 않는다.
- 렌더에서 `const_cast`로 물리 상태를 수정하지 않는다.

### 10.1 광 연결의 모델 확장

현재 `PortType`은 전기/공압만 있고 `Wire`에는 `isElectric`만 있다.
광화이버 연결에는 별도의 광 타입과 TX/RX 역할이 필요하다.

- 배선 종류를 명시적 enum으로 확장하되 구버전 `is_electric`을 읽는
  호환 경로를 둔다. 전기/공압 포트 ID는 변경하지 않는다.
- 증폭부 TX → 송신 헤드, 수신 헤드 → 증폭부 RX를 연결한다.
  헤드의 전기 신호를 직접 PLC에 보내는 가상의 핀을 만들지 않는다.
- 감지 대상과 실제 감지 구간은 헤드의 배치/방향/높이로 결정한다.
  증폭부 자체의 XY/Z를 외부 감지 위치로 쓰지 않는다.
- 전선/호스와 마찬가지로 광 케이블도 서로 다른 설치 높이를 연결할 수
  있다. 높이 일치가 필요한 것은 헤드와 공작물의 감지 구간이다.
- TX/RX 광 연결과 전원 상태를 검증한 뒤 증폭부 전기 출력으로 감지를
  전달한다. 연결선의 화면 교차를 물리 접속으로 취급하지 않는다.
- 광 출력 색상과 전기 센서 출력 색상을 구분한다. 엔코더/통신/PE도
  색상만으로 의미를 구분하지 않고 역할 라벨·연결 규칙으로 구분한다.
- 전기/공압/광 모두 단일 배선 도구로 연결한다. 광 전용 모드 선택은
  추가하지 않는다. 별도 회로 편집기나 물리 광선 추적 엔진은 도입하지 않는다.

### 10.2 단일 배선 도구와 핀 기반 자동 타입

핀 타입 외에 DC 전원/AC 전력/서보 상/엔코더/통신/진공/광 역할을
[부품 명세 2절](WIRING_NEW_COMPONENT_SPEC.md#2-공통-포트와-신호-규칙)에 정의한다.
같은 전기 또는 공압 타입이라는 이유만으로 모든 핀 조합을 허용하지 않는다.

사용자 확정 요구사항: 툴바의 `공압 배선`, `전기 배선`을 `배선 도구`
하나로 바꾸고, 광 연결도 같은 도구에 포함한다. 배선 임베딩/태그 기능은
별도 용도이므로 이번 종류 통합만으로 제거하거나 합치지 않는다.

| 사용 단계 | 처리 |
| --- | --- |
| 배선 도구 선택 | 아직 배선 종류를 정하지 않음 |
| 시작 핀 클릭 | 실제 포트 정의의 타입으로 진행 중 연결 종류를 결정 |
| 중간 점 추가 | 시작 핀에서 결정한 종류 유지. 전기/공압/광 기본 스타일로 미리보기 |
| 대상 핀 호버 | 타입과 역할이 호환되는 핀만 유효 대상으로 강조 |
| 대상 핀 클릭 | 같은 검증을 다시 수행한 뒤 연결 생성 |
| 잘못된 대상 클릭 | 선을 생성하지 않음. 기존 시작점/중간 점 유지, 간단한 이유 표시 |
| 취소 / 도구 변경 | 시작 핀·중간 점·자동 결정된 타입을 함께 초기화 |

- `ToolType`의 공압/전기 도구를 통합 배선 도구로 대체한다. 코드 예시 이름은
  프로젝트 가이드에 맞춘 `kWire`를 사용하되 기존 enum과의 이행은 구현 시 정리한다.
- 시작 핀 타입은 색상, 이름 문자열, 현재 Z, 마지막 사용한 종류로 추정하지 않는다.
  부품 정의 또는 RTL runtime port의 `PortType`이 기준이다.
- 현재 코드의 `newWire.isElectric = (current_tool_ == ToolType::ELECTRIC)`와
  임시 선 색상 도구 의존을 제거한다. 진행 상태에 시작 포트와 명시적 연결
  종류를 보관하고 완료 시 시작 포트가 아직 존재하는지도 재검증한다.
- 전기↔공압, 전기↔광, 공압↔광은 연결 불가.
- 같은 타입 안에서는 역할별 실제 연결 규칙을 적용한다. 전기/공압에
  `isInput`이 같다는 이유만으로 일괄 금지하지 않는다. 전원 분기와
  공압 분배가 기존과 동일하게 가능해야 한다.
- 광은 증폭부 TX와 송신 헤드, 수신 헤드와 증폭부 RX처럼 포트 역할을
  검사한다. 어느 끝을 먼저 클릭해도 동일한 연결이 성립한다.
- 동일 핀 자기 연결과 중복 선의 처리, 포트별 최대 연결 수는 공통 검증에
  둔다. 전기 분기/공압 분배와 광 포트의 연결 수 제약을 구분한다.
- 전압 수준 및 기존 SINK/SOURCE, PNP/NPN 검증을 도구 통합으로 우회하지 않는다.
- 다른 Z의 핀도 선/호스/광 케이블로 연결 가능하다. 물리 접촉 높이 규칙을
  케이블 연결 검증에 잘못 적용하지 않는다.
- 툴바, Q 도구 순환, 단축키 도움말, 상태바, 포트 툴팁과 한/영/일 번역을
  같이 변경한다. 각 언어에 오래된 공압/전기 도구 선택 설명을 남기지 않는다.
- `Wire`의 연결 종류 enum을 렌더·전기/공압/광 네트워크·필터·저장·Undo가
  함께 읽는다. bool과 enum을 독립적으로 쓰는 이중 진실 구조를 피한다.

구버전 저장 파일의 `is_electric`은 로드 시 명시적 연결 종류로 변환한다.
새 파일에는 연결 종류를 저장하고 두 끝 포트와 일치하는지 검사한다.
저장 종류와 포트 타입이 다르면 손상된 연결로 보고 유효 연결로 처리하지
않는다. 로드 시 포트 색상으로 종류를 조용히 바꾸지 않는다.

## 11. 저장·불러오기·Undo

배치 JSON 버전은 2에서 3으로 올리는 안을 제안한다. `.plcproj`에 포함되는
배치와 단독 실배선 저장이 동일한 직렬화 함수를 쓰는지 함께 검증한다.

저장 구조 예시:

```json
{
  "version": 3,
  "z_layers": {"count": 3},
  "components": [{
    "instance_id": 10,
    "type": "<신규 일체형의 확정 타입 이름>",
    "z_order": 8,
    "z_config": {"min_layer": 1, "max_layer": 3, "initial_height": 3},
    "view_mode": "top"
  }]
}
```

위 예시는 스키마 제안이며 현재 읽을 수 있는 프로젝트 파일은 아니다.

- 레이어 수, 설치/이동 범위, 초기 위치, 표시 모드, 슬롯 높이,
  초기 적재 공작물 참조를 명시적으로 저장.
- 일반 프로젝트 불러오기는 초기 상태를 구성한다. 이동 중 속도·접촉
  캐시·임시 흡착 상태 전체를 암묵적으로 저장/복원하지 않는다.
- 현재 창고 재고를 보존하려면 저장 시 현재 점유를 초기 적재로 확정하는
  옵션을 제공한다. 이 경우 공작물 ID·재질·가공 상태·높이도 함께 보존.
- 런타임 전체 스냅샷 기능은 별도 기능이며 이번 필수 범위에 넣지 않는다.
- 이전 JSON: 고정 부품과 공작물은 높이 1로 읽고, 가공 실린더는 기본
  범위 1~2를 부여. 기존 배선·라벨·회전·그리기 순서는 유지.
- 구버전 가공 헤드의 상승 상태 XY 스냅은 Z 도입으로 달라질 수 있으므로
  의도적인 동작 변경으로 회귀 테스트와 변경 기록에 명시한다.
- 현재 Undo는 부품을 복사하지만 레이어 수와 슬롯 초기 설정까지 복원하는지
  추가 확인. 하나의 입력 편집은 하나의 Undo 동작으로 기록.
- 설정 Undo와 시뮬레이션 진행의 되감기를 혼동하지 않도록 한다.
- 무효 ID, 중복 점유, 범위 밖 높이는 부분 적용하지 않고 검증 후 일괄 적용.

## 12. 구현 단계와 완료 조건

| 단계 | 작업 | 완료 조건 |
| --- | --- | --- |
| 1. 기반 정리 | 공통 렌더·실린더·등록 정리, 높이 모델, Wire 종류 enum 및 배선 도구 통합 | 기존 포트 ID/배선 호환 유지, 핀 기반 자동 종류 검증 |
| 2. 고정 높이 | 공작물·컨베이어·센서·실린더·박스에 Z 적용. Box2D/폴백/고급 경로 정리 | 같은 XY의 다른 Z는 모든 효과에서 분리 |
| 3. 저장/UI 기반 | JSON 마이그레이션, Undo, 더블클릭 Z 편집, 사이드 창 | 저장/복원과 편집 취소가 일관됨 |
| 4. 기존 가공 + 신규 실린더 | 가공 Z 매핑, 센서 내장형, 흡착형, 스토퍼 | 실배선 구동과 높이 접촉·수납 상태 확인 |
| 5. 서보 축/일체형 | 모터·앰프·리프트 지령 연결, XY/Z 독립, 흡착 소유 상태 | 공작물이 리프트 높이를 추종하고 다른 높이에 영향 없음 |
| 6. 창고 | 6슬롯과 높이별 적재/해제, 초기 재고 저장, 호버/적재 오버레이 | 3번→2번 적재와 점유 충돌 처리 검증 |
| 7. 광화이버/HMI | 광 연결과 높이 감지, 패널 제어/표시 | 증폭부 전기 신호와 헤드 감지가 실제 배선에서 연결 |
| 8. 통합 | 전체 시안 반영, 최적화·회귀·공정 테스트 | 아래 통합 테스트와 수동 확인 모두 통과 |

각 단계는 동작하는 작은 단위로 진행한다. 신규 타입마다 물리 처리 코드를
통째로 복사하지 않는다. 포트 수를 별도 switch에 반복 기록하는 부분도
정의 정보에서 얻도록 정리한다. 사용 여부가 불명확한 레거시 함수의
대규모 삭제는 이번 변경과 분리한다.

## 13. 검증 계획

[부품 명세 14절](WIRING_NEW_COMPONENT_SPEC.md#14-구현-계약과-검증)의
배선→구동→물리 효과→PLC 피드백 경로를 아래 통합 검증과 함께 적용한다.

테스트는 구현 복제가 아니라 실제 공유 함수 및 앱 경로를 사용한다.

### 높이와 상호작용

- 같은 XY/같은 높이: 이송·감지·가공·차단 가능.
- 같은 XY/다른 높이: 이송·감지·스냅·가공·흡착·상자 저장 모두 발생하지 않음.
- 그리기 순서를 바꿔도 결과 동일. Z만 바꾸면 XY 변화 없이 결과 변경.
- 높이 1.49/1.51을 레이어 1/2로 반올림해 상호작용시키지 않음.
- 범위 1~3이지만 현재 3인 리프트는 높이 1 공작물을 흡착하지 않음.
- 범위 4~6으로 이동한 리프트도 같은 상대 동작 가능.
- Box2D 최대 index 질의가 다른 높이의 상자를 건너뛰고 올바른 후보 선택.
- 폴백·고급 경로·오프스크린·수면 상태에서도 동일한 결과.

### 구동·흡착·창고

- 가공 상승 2에서는 높이 1 공작물에 영향 없음. 하강 1 + 모터 ON에서만 가공.
- 스토퍼 상승 시 공작물 통과, 하강 시 차단. 기본 렌더에 축 노출 없음.
- 리프트 흡착 공작물의 XY/Z 동시 추종. 이동 중 컨베이어가 끌고 가지 않음.
- 같은 위치 다른 높이의 두 공작물 중 하나만 흡착.
- 슬롯마다 1개, 단마다 2개, 총 6개 제한.
- 비금속 3번→2번 적재, 금속 배출박스 수납을 PLC 지령으로 수행.
- 목표 높이 미도착/슬롯 점유/잘못된 높이에서 적재 실패, 기존 재고 보존.
- 소유 부품 삭제·리셋·정지/재개 시 참조 정합성.
- 엔코더 지령/실제 위치/도착 신호와 Z 위치가 일치하며 HMI에 표시.
- 광 연결과 증폭부 전원 없이는 감지 출력이 발생하지 않음.

### 통합 배선 도구

- 한 도구에서 전기 핀으로 시작하면 전기선, 공압 핀은 호스, 광 핀은
  광 연결이 생성되고 미리보기/완성 선의 종류가 일치함.
- 종류가 다른 대상 핀을 클릭하면 연결이 생성되지 않고 진행 상태가 유지됨.
- 중간 점을 추가해도 종류가 변하지 않음. 취소 후 다른 종류로 시작하면
  이전 타입과 중간 점이 남지 않음.
- 시작 부품 삭제/포트 변경 후 완료를 시도하면 잘못된 참조를 생성하지 않음.
- 어느 끝에서 시작해도 전기·공압 및 유효한 TX/RX 역할 쌍의 결과가 동일함.
- 전원 분기와 공압 매니폴드의 다중 연결 유지. 광 역할/연결 수 위반은 거부.
- Z가 다른 핀의 연결, 구버전 `is_electric` 로드, 신버전 종류 저장,
  Undo/Redo 및 네트워크 분류까지 검증.

### UI·저장

- 평면 기본 배치, 정면 확인, 창고 호버/적재 오버레이.
- 표시 전환 전후 포트 ID/전선 위치/높이/물리 결과 동일.
- 다른 Z에 겹친 부품을 레이어 창에서 각각 선택·편집 가능.
- 기존 버튼/비상정지 더블클릭 조작과 새 메뉴 접근 모두 가능.
- 구버전 프로젝트 로드, 신버전 round-trip, Undo/Redo, 복사/붙여넣기.
- 축 범위 밖 값·NaN·중복 슬롯 소유 입력 거부.
- 240Hz 물리 스텝과 PLC 스캔 사이에 stale 센서/높이 결과 없음.

현재 테스트 대상인 `ladder_physical`, `application_runtime` 및 기존
배선 관련 테스트를 변경 규모에 맞춰 실행한다. 테스트 이름만 통과시키지
말고 전기 배선 → 앰프/솔레노이드 → 축 이동 → Z 접촉 → 센서 → PLC 입력
및 적재의 실제 경로를 포함한다.

## 14. 구현 전 확정이 필요한 세부사항

이 항목들은 본 계획의 기본 방향을 막지 않지만 해당 기능 착수 전에
확정해야 한다. 현재 문서는 제안값을 요구사항과 구분해서 기록한다.

1. `가공 리프트`가 서보 리프트를 뜻하는지, 별도 타입인지.
2. `수평으로 보기`가 메뉴 내 정면 미리보기면 충분한지, 캔버스 표시도
   전환할지. 우선안은 물리를 바꾸지 않는 정면 미리보기다.
3. 스토퍼 상승/하강 높이와 접촉 허용 오차. 기본 제안은 2/1.
4. 서보앰프의 정확한 제어 모델과 I/O 할당. 사진의 특정 모델이 지원하는
   통신 방식과 임의 펄스 입력을 섞지 않도록, 지령 인터페이스부터 확정한다.
5. 현재 재고를 프로젝트 저장에 기본 포함할지, 초기 재고로 확정하는
   옵션으로 둘지. 우선안은 설정/초기 재고와 런타임을 구분하는 방식이다.

## 15. 이번 작업의 결과

현재 구현 연결 지점, 높이·소유·슬롯 모델, UI와 저장 정책,
단계별 구현 및 검증 기준을 정리했다. 이 문서와 디자인 참고 파일만 추가하며
시뮬레이터 소스, 기존 프로젝트, 기능 동작은 변경하지 않는다.
