# RTL Tool Doctor：WSL2の準備と問題解決

[使い方の目次](README.ja.md) · [RTL部品の作成](12-rtl.ja.md)

Tool Doctorは **RTL解析・ビルド・テストベンチに必要な環境** を確認・管理する画面です。
Verilog部品の新規作成や、修正したソースの再ビルドに使います。
ビルド済みWindows RTL部品EXEの実行にはWSLは不要です。

<a id="창을-열고-결과-읽기"></a>

## 画面を開き結果を読む

**RTL → ツールチェーン** で **RTLツール診断（WSL2）** を開きます。
開くと保存済み環境を自動診断します。診断中はボタンが無効になります。

![Tool Doctorの診断結果](../../images/program-guide/06-rtl-doctor.png)

| 表示 | 読み方 |
| --- | --- |
| ディストリビューション | 解析・ビルド用WSL環境。インストール済みの名前を選択 |
| 既定のディストリビューション | Windows WSLの既定を使用。必ずUbuntuとは限らない |
| ビルドCPU使用量 | **同時ビルドジョブ数**。CPU使用率ではない。既定2、範囲1～64 |
| 保存して診断 | 選択した環境とCPU値を保存し、その設定を診断 |
| 保存済み環境を診断 | 最後に保存した設定を検査。未保存の選択は適用されない |
| 検出済み／未検出 | 検査の成否。展開するとコマンド出力やバージョンを確認可能 |

WSLと環境の検査に通ると、カーネル・ビルドツールまで計7項目が表示されます。
**すべて検出済みならインストールは不要です。** 画面を閉じて、
[RTLライブラリで解析・ビルド](12-rtl.ja.md) を進めてください。

<a id="wsl-환경이-없는-pc에서-처음-준비하기"></a>

## WSLがないPCでの初期設定

1. **WSL2／Ubuntuをインストール** を押します。Ubuntuのインストールを要求するボタンです。
   Windowsの管理者承認や再起動の案内に従います。
2. インストール後、**保存済み環境を診断** で環境一覧を更新します。
   再起動した場合はアプリとTool Doctorを開き直します。
3. **ディストリビューション** でインストール済みの **Ubuntu [WSL2]** を選びます。
   既存のUbuntu/Debian WSL2があれば、その名前を選んでも構いません。
4. ビルドジョブ数を決め、**保存して診断** を押します。
5. ツールが足りなければ **RTLツールのインストール／修復** を押します。
   選択環境内にVerilator・g++・MinGW-w64・makeをインストールします。
6. 作業後の自動診断を読み、必要なら **保存済み環境を診断** で再確認します。

インストール完了のメッセージだけで判断せず、各診断項目を確認します。
Ubuntuインストール後も環境がない、初期設定エラーが出る場合はUbuntuを直接開き、
表示された初期設定を終えてから再診断してください。

ツールのインストールは **Ubuntu/Debianのapt** を使います。別の環境を選んでも、
その環境のパッケージ管理方式に合わせるわけではありません。
ダウンロードやインストールには時間がかかるため、完了ログを待ちます。

<a id="없음이-나왔을-때"></a>

## 未検出と表示された場合

まず失敗項目を展開して詳細を読み、次の表で該当する対処を選びます。

| 失敗項目・状況 | 対処 |
| --- | --- |
| WSLホスト | WSL一覧取得の失敗。エラーを読み、未導入なら **WSL2／Ubuntuをインストール** |
| WSL2環境：名前がない | 導入済み名を選び **保存して診断**。環境がなければUbuntuをインストール |
| WSL1と表示 | 選択して **選択環境をWSL2に変換** 後、診断 |
| Linuxカーネル | 起動エラーを読み、WSL更新・再起動が必要か確認 |
| Verilator | **5.x以上** が必要。古い版も未検出になる。修復後も失敗なら詳細のバージョンを確認 |
| C++コンパイラー／make | 選択Linux環境のg++・makeが必要。Ubuntu/Debianでは **RTLツールのインストール／修復** |
| MinGW Windowsコンパイラー | **WSL内のWindows用クロスコンパイラー** が必要。Windows側のMinGWではこの検査に通らない |
| インストール・修復失敗 | 下のログのapt・ダウンロード・環境エラーを読み、原因を直して再実行 |

WSLホストまたはWSL2環境で失敗すると、検査はそこで止まります。
その段階でツール項目が出ないのは正常です。先の失敗を直して再診断します。

未検出はファイル不在だけでなく、コマンド実行失敗や非対応バージョンも含みます。
診断は選択環境の `/usr/bin` を検査するため、別の場所に手動で入れたツールが
自動的に使われるとは限りません。

<a id="관리-버튼을-쓰는-경우"></a>

## 管理ボタンを使う場合

管理前に **環境名を明示的に選んで保存** すると、対象を区別しやすくなります。

| ボタン | 動作と用途 |
| --- | --- |
| WSL2／Ubuntuをインストール | WSL・Ubuntuのインストール要求。選択名の環境を導入するボタンではない |
| RTLツールのインストール／修復 | 選択したWSL2 Ubuntu/Debianにビルドツールを導入 |
| 選択環境を起動 | 選択した環境を実行 |
| 選択環境を停止 | 環境を終了。内部の他の実行中プログラムも終了 |
| 選択環境をWSL2に変換 | 導入済みWSL1環境をWSL2へ変更 |
| WSL更新 | WindowsのWSLを更新。RTLツール導入とは別 |

**診断でも環境が起動する場合があります。** 停止後に診断すると再起動することがあります。
停止成功後は古い診断一覧を消し、自動で再診断はしません。

下のログはインストール・起動・停止などの **管理作業の結果**、
各診断項目の展開部分は **その検査コマンドの結果** です。
管理中に画面を閉じても作業は中止されません。
診断・管理・RTL解析・ビルド中は、Doctorの設定・管理ボタンが無効になる場合があります。

<a id="환경이-준비된-다음"></a>

## 環境準備後

Doctorを閉じ、**RTL → RTLライブラリ** でソースを解析・ビルドします。
WSLのLinuxツールで解析・テストベンチを実行し、WSLのMinGW-w64で
実配線で使う **Windowsネイティブ部品EXE** を作ります。

設定後は [RTL部品の作成と使用](12-rtl.ja.md) を続けて読んでください。
