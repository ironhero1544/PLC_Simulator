# RTL Tool Doctor: WSL2 환경 준비와 오류 해결

[사용법 목차](README.md) · [RTL 부품 만들기](12-rtl.md)

Tool Doctor는 RTL의 **분석·빌드·테스트벤치에 필요한 환경**을 검사하고 관리하는 창입니다.
새 Verilog 부품을 만들거나 소스를 수정해 다시 빌드할 때 사용합니다.
이미 빌드된 Windows RTL 부품 EXE를 실행하는 데에는 WSL이 필요하지 않습니다.

## 창을 열고 결과 읽기

**RTL → 툴체인**을 누르면 **RTL 도구 진단 (WSL2)** 창이 열립니다.
창을 처음 열면 저장된 환경을 자동으로 검사합니다. 진단 중에는 버튼이 비활성화됩니다.

![앱의 Tool Doctor 진단 결과](../../images/program-guide/06-rtl-doctor.png)

| 표시 | 읽는 방법 |
| --- | --- |
| 배포판 | 분석·빌드에 사용할 WSL 환경. 설치된 이름을 선택합니다 |
| 기본 배포판 | Windows WSL에 설정된 기본 배포판을 사용합니다. 항상 Ubuntu라는 뜻은 아닙니다 |
| 빌드 CPU 사용량 | **동시에 실행할 빌드 작업 수**입니다. CPU 사용률(%)이 아닙니다. 기본 2, 범위 1~64 |
| 저장 후 진단 | 지금 선택한 배포판과 CPU 값을 저장하고 그 설정을 검사합니다 |
| 저장된 환경 진단 | 마지막으로 저장한 설정을 다시 검사합니다. 아직 저장하지 않은 선택은 적용되지 않습니다 |
| 찾음 / 없음 | 해당 검사 통과 여부. 항목을 펼치면 명령 출력과 버전 등을 볼 수 있습니다 |

WSL과 배포판 검사를 통과하면 커널과 빌드 도구까지 총 7개 항목이 나옵니다.
**모두 ‘찾음’이면 설치 버튼을 누를 필요가 없습니다.** 창을 닫고
[RTL 라이브러리에서 분석·빌드](12-rtl.md)를 진행하세요.

## WSL 환경이 없는 PC에서 처음 준비하기

1. **WSL2 / Ubuntu 설치**를 누릅니다. 이 버튼은 Ubuntu 설치를 요청합니다.
   Windows의 관리자 승인이나 재시작 안내가 나오면 안내를 따릅니다.
2. 설치 작업이 끝난 뒤 **저장된 환경 진단**을 눌러 배포판 목록을 갱신합니다.
   재시작했다면 앱을 다시 열고 Tool Doctor를 엽니다.
3. **배포판**에서 설치된 **Ubuntu [WSL2]**를 선택합니다.
   이미 사용할 Ubuntu/Debian WSL2 환경이 있다면 그 이름을 선택해도 됩니다.
4. 빌드 작업 수를 정하고 **저장 후 진단**을 누릅니다.
5. 도구 항목이 부족하다면 **RTL 도구 설치 / 복구**를 누릅니다.
   선택한 배포판 안에 Verilator·g++·MinGW-w64·make를 설치합니다.
6. 작업 후 자동 진단 결과를 읽습니다. 필요하면 **저장된 환경 진단**으로 다시 검사합니다.

설치 완료 메시지만으로 도구 준비 여부를 판단하지 않습니다. 진단 결과에서 각 항목을 확인합니다.
Ubuntu 설치 후에도 배포판이 없거나 초기 설정 오류가 나오면, 설치된 Ubuntu를 직접 열어
표시되는 초기 설정을 마친 뒤 다시 진단하세요.

도구 설치는 **Ubuntu/Debian의 apt**를 사용합니다. 다른 배포판을 선택했다고
그 배포판의 패키지 관리자에 맞춰 설치되는 것은 아닙니다.
다운로드나 설치에 시간이 걸리므로 작업 중에는 완료 로그를 기다립니다.

## ‘없음’이 나왔을 때

실패한 항목을 먼저 펼쳐 상세 출력을 읽으세요. 아래 표에서 해당 상황의 조치를 선택합니다.

| 실패 항목·상황 | 조치 |
| --- | --- |
| WSL 호스트 | WSL 목록 조회가 실패한 상태입니다. 상세 오류를 읽고, 미설치라면 **WSL2 / Ubuntu 설치**를 사용합니다 |
| WSL2 배포판: 선택한 이름이 없음 | 배포판 목록에서 설치된 이름을 다시 선택하고 **저장 후 진단**합니다. 배포판이 없다면 Ubuntu를 설치합니다 |
| WSL2 배포판: WSL1로 표시 | 해당 배포판을 선택하고 **선택 배포판을 WSL2로 전환**한 뒤 진단합니다 |
| Linux 커널 | 배포판 실행 오류를 읽습니다. WSL 업데이트·재시작이 필요한 오류인지 확인합니다 |
| Verilator | **5.x 이상**이 필요합니다. 실행 파일이 있어도 이전 버전이면 ‘없음’으로 표시됩니다. 설치/복구 후에도 실패하면 상세 버전을 확인합니다 |
| C++ 컴파일러 / make | 선택한 Linux 배포판의 g++ 또는 make가 필요합니다. Ubuntu/Debian에서는 **RTL 도구 설치 / 복구**로 설치합니다 |
| MinGW Windows 컴파일러 | **WSL 안의 Windows용 교차 컴파일러**가 필요합니다. Windows에 설치한 MinGW는 이 검사를 만족시키지 않습니다 |
| 설치/복구 실패 | 창 아래 작업 로그에서 apt·다운로드·배포판 오류를 읽고 해당 원인을 해결한 뒤 다시 실행합니다 |

WSL 호스트 또는 WSL2 배포판에서 실패하면 검사 자체가 거기서 멈춥니다.
도구 항목이 아직 나오지 않는 것은 정상입니다. 앞선 실패를 해결한 뒤 다시 진단하세요.

‘없음’은 단순히 파일이 없다는 뜻만은 아닙니다. 명령 실행 실패나 지원하지 않는 버전도 포함합니다.
진단은 선택한 배포판의 `/usr/bin` 도구를 검사하므로 다른 위치에 수동 설치한 도구가
자동으로 사용된다고 가정하지 않습니다.

## 관리 버튼을 쓰는 경우

관리 작업 전에 **배포판 이름을 명시적으로 선택하고 저장**하면 대상 환경을 구분하기 쉽습니다.

| 버튼 | 동작과 사용할 상황 |
| --- | --- |
| WSL2 / Ubuntu 설치 | WSL·Ubuntu가 없는 PC에서 설치 요청. 선택한 이름의 배포판을 설치하는 버튼은 아닙니다 |
| RTL 도구 설치 / 복구 | 선택한 WSL2 Ubuntu/Debian에 빌드 도구 설치 |
| 선택 배포판 시작 | 선택한 배포판을 실행 |
| 선택 배포판 중지 | 선택한 배포판을 종료. 그 안에서 실행 중인 다른 프로그램도 종료됩니다 |
| 선택 배포판을 WSL2로 전환 | 설치된 WSL1 배포판을 WSL2로 변경 |
| WSL 업데이트 | Windows의 WSL을 업데이트. RTL 도구 설치와는 별도입니다 |

**진단도 배포판을 실행할 수 있습니다.** 중지 후 진단을 누르면 다시 시작될 수 있습니다.
중지 작업에 성공하면 창의 기존 진단 목록은 지워지고 자동 재진단하지 않습니다.

창 아래의 로그는 설치·시작·중지 같은 **관리 작업 결과**이고,
각 진단 항목을 펼쳤을 때 보이는 내용은 **그 검사 명령의 결과**입니다.
관리 작업 중 창을 닫아도 작업이 취소되지 않습니다.
진단·관리 작업 또는 RTL 분석/빌드가 진행 중이면 Doctor의 설정·관리 버튼이 비활성화될 수 있습니다.

## 환경이 준비된 다음

Doctor 창을 닫고 **RTL → RTL 라이브러리**에서 소스를 분석하고 빌드합니다.
WSL의 Linux 도구로 분석·테스트벤치를 실행하고, WSL의 MinGW-w64로
실배선에서 실행할 **Windows 네이티브 부품 EXE**를 만듭니다.

환경 설정을 마쳤다면 [RTL 부품 만들기와 사용](12-rtl.md)을 이어서 읽으세요.
