# 12. RTL 부품 만들기와 사용

RTL은 Verilog로 만든 회로를 실배선 부품으로 활성화하는 기능입니다.
기본 래더 실습에는 필요하지 않으므로 해당 실습을 마친 뒤 진행해도 됩니다.

직접 배치하고 배선하는 예제는 [Full Adder 실배선 실습](rtl-full-adder.md)을 이어서 읽으세요.
소스 코드부터 전원·입출력 연결, 버튼 조작과 진리표까지 설명합니다.

## 먼저 빌드 환경 준비하기

**RTL → 툴체인**에서 WSL2 환경을 진단합니다.
처음 설치하는 순서와 오류별 조치는 [Tool Doctor 사용법](rtl-tool-doctor.md)에 설명했습니다.
진단 항목이 모두 ‘찾음’이면 아래의 부품 제작으로 진행합니다.

새 부품을 빌드하거나 테스트할 때는 WSL2 환경이 필요합니다.
이미 빌드된 부품은 WSL 설치 없이 사용할 수 있습니다.

## 1단계: RTL 모듈 준비

![RTL 라이브러리의 새 RTL 모듈 버튼](../../images/program-guide/rtl-01-library.jpg)

*RTL → RTL 라이브러리에서 왼쪽 위 ‘새 RTL 모듈’을 누릅니다.*

1. **RTL → RTL 라이브러리**를 엽니다.
2. **새 RTL 모듈**을 누르고 알아보기 쉬운 이름으로 만듭니다.
3. 새 파일을 만들려면 **소스 목록 우클릭 → 파일 추가**를 누릅니다.
   기존 `.v` 파일은 편집 영역 위의 **가져오기**로 불러옵니다.
4. 파일을 선택하고 **TOP으로 설정**합니다. TOP 모듈명은 소스의 module 이름과 맞춥니다.
5. 테스트벤치 파일이 있으면 추가하고 **TB로 설정**합니다.
   위쪽 **테스트벤치 탑 모듈**에도 해당 소스의 module 이름을 입력합니다.
6. 소스를 편집하고 **분석**을 실행합니다.
7. 오류가 없으면 **빌드**를 실행합니다.

![새 모듈의 TOP 소스와 편집 영역](../../images/program-guide/rtl-02-source-top.jpg)

*왼쪽은 파일 선택, 오른쪽은 소스 편집입니다. [TOP]은 부품으로 만들 파일입니다.*

![소스 목록 우클릭 메뉴의 파일 추가](../../images/program-guide/rtl-03-add-file.jpg)

*‘파일 추가’는 소스 목록의 우클릭 메뉴에 있습니다. 빈 파일을 만든 뒤 코드를 입력합니다.*

![TOP 파일과 TB 파일 및 테스트벤치 모듈명](../../images/program-guide/rtl-05-testbench-top.jpg)

*TB 소스의 `module guide_tb`와 위쪽 ‘테스트벤치 탑 모듈’의 `guide_tb`를 맞춥니다.*

![분석 성공 상태와 입출력 포트 목록](../../images/program-guide/rtl-04-analysis.jpg)

*분석 후 아래에 ‘분석 상태: 성공’과 입력·출력 포트가 나타납니다.*

분석은 소스와 포트를 확인하는 단계이고 빌드는 실행할 부품을 만드는 단계입니다.
분석 성공만으로 새 실행 파일이 준비된 것은 아닙니다.

![빌드 성공 상태와 부품 활성화 위치](../../images/program-guide/rtl-06-build.jpg)

*‘빌드 상태: 성공’이 나오면 실행 파일이 만들어진 상태입니다.
그 아래 ‘부품으로 활성화’가 실배선 목록에 등록하는 설정입니다.*

## 2단계: 테스트와 실배선 사용

1. TB를 지정한 경우 **테스트벤치 실행**을 누릅니다.
2. 결과 PASS/FAIL/TIMEOUT과 테스트벤치 로그를 확인합니다.
3. 파형이 생성되면 **파형 열기**에서 신호 변화를 확인합니다.
4. 빌드된 모듈의 **부품으로 활성화** 설정을 켭니다.
5. 실배선 부품 목록에서 해당 RTL 부품을 배치합니다.
6. 입력·출력 포트를 연결하고 운전 결과를 확인합니다.
7. 전체 프로젝트를 `.plcproj`로 저장합니다.

![테스트벤치 통과 결과](../../images/program-guide/rtl-07-testbench-pass.jpg)

*PASS는 테스트 통과를 뜻합니다. 결과 영역이 잘리면 아래 패널 안에서 스크롤하세요.*

소스를 바꾼 뒤에는 분석·빌드를 다시 합니다. 테스트벤치가 NOT RUN인 상태는 검증에 통과했다는 뜻이 아닙니다.
GUI에 표시되는 포트 이름과 실제 TOP의 입출력이 일치하는지 확인합니다.

## 부품 공유와 다시 편집하기

| 목적 | 저장 방법 |
| --- | --- |
| 다른 프로젝트에서 부품 재사용 | 부품 내보내기 → `.plccomp` |
| 받는 사람이 소스도 수정·재빌드 | 내보낼 때 소스 포함 선택 |
| 실행만 가능한 부품 배포 | 런타임 전용 패키지 |
| 배선·래더·RTL을 함께 보관 | `.plcproj` 통합 저장 |

라이브러리의 **부품 가져오기**로 `.plccomp`를 엽니다.
빌드 폴더의 worker EXE를 별도 새 RTL 모듈처럼 다시 가져오지 않습니다.
소스가 없는 런타임 패키지는 사용할 수 있어도 소스 편집·재빌드는 할 수 없습니다.

빌드된 Windows 부품 EXE가 포함된 패키지는 실행 시 WSL을 사용하지 않습니다.
새 부품을 빌드하거나 테스트벤치를 돌릴 때 WSL2 환경을 준비합니다.

환경에 문제가 생기면 [Tool Doctor 오류 해결](rtl-tool-doctor.md)을 참고하세요.
